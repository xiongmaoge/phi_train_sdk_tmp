# 后续改进计划

> 记录当前已知的改进点与欠账，按优先级大致排序。日期：2026-09-18。

## 安全

1. **start.sh 硬编码 API key**：`SERVICE_API_KEY` 默认值 `foresee123` 写死在已提交脚本里 → 改为无默认值（必填）或启动时随机生成，历史 key 轮换。
2. **root 密码轮换**：集群 root 密码曾出现在本地 `.qoder` 历史中（已清理），建议尽快轮换。
3. **conf.json 凭证管理**：phi_data_server 的 `conf/conf.json` 含凭证，已加 .gitignore；部署时只放服务器 `/mnt/conf/`，不入库。

## 配置与数据源一致性

4. **phi_data_sdk 同步切换端点**：`/storage/query` → `/conf/query` 目前只改了 phi_train_slurm 客户端（旧端点线上已 404）；数据侧 phi-sync 若仍调旧端点需同步切。
5. **线上 conf.json 字段**：`default` / `ehpc_hz` 条目目前只有基础字段（host/user/port/identity_file/desc）。`remote_tmp_dir` / `defaults` / `paths` 按需补充——注意 YAML 默认值注入方案已否决（defaults 不回填 JobSpec）。
6. **paths 段待确认**：只确认了 CPFS 挂载点 `/ehpcdata`、`/opt`、`/home`；`/ehpcdata` 下的数据集 / checkpoint 实际子目录未确认。

## 功能缺口

7. **GPU 链路未验证**：集群只有 `comp` 分区（无 gpu）；pyxis 容器（`--container-image`）、torchrun 多机启动未在真实 GPU 队列跑过。`examples/exp_vla.yaml` 与 `docs/系统设计文档.md` 里的 `partition: gpu`、`/mnt/cpfs/*` 是设计稿值，接入 GPU 后需对齐为 `comp`、`/ehpcdata`、`/home/phi_logs`。
8. **requeue 托管**：requeue 对确定性代码错误也会重试到上限；`wait()` 重提交依赖调用方进程存活 → 可考虑把 wait/requeue 托管到 apiserver 常驻进程。
9. **hold/release 透出**：`scontrol hold/release` 已在 `SlurmBackend` 实现，manager / handle / CLI 未透出。
10. **SSH 建连开销**：每命令一次 SSH 建连 → 后续可演进为登录节点常驻 HTTP 网关（只换 backend，接口不变）。
11. **Slurm 任务网页**：目前没有 Slurm 任务详情/日志的网页入口（现有 dashboard 是 Ray 作业专用）。可考虑在 apiserver 加 `GET /slurm/job/<id>`：服务端 SSH 登录节点拼 `scontrol show job` + `sacct` + 日志尾部渲染成 HTML，浏览器直达。

## 成本与运维

12. **闲置资源释放**：计算节点 serverless 空闲自动关机（已确认，不收费）；但登录节点 ECS + EIP + CPFS 容量持续计费。不用时：控制台停止登录节点、释放 EIP；CPFS 删除=数据丢失，删前备份到 OSS。建议写成 runbook 或脚本。
13. **账单核对**：在阿里云费用中心确认 `idle~` 节点确实不产生 ECS 计费、CPFS 计费项符合预期。
